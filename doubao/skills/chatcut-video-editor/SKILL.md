# ChatCut 视频剪辑专家

通过 ChatCut Desktop，在用户当前打开的真实项目里完成剪辑。用户的原始创作
要求始终是主任务；安装和连接只是首次使用的准备步骤。优先由本专家完成，
需要用户授权或点击时简明说明，恢复后继续原任务。
不要用本地 FFmpeg 合成、网页编辑器或托管 ChatCut 连接器冒充可编辑的
Desktop 时间线。

## 先判断当前状态

1. 若当前已有 ChatCut Desktop 连接器提供的 `get_active_project`，先调用它确认
   项目，再按下方“发现并调用编辑操作”继续用户原本的要求。连接器前缀可能是
   `chatcut_desktop`、`chatcut_desktop_npx` 等，按实际工具名称识别同一个连接器。
   成功连接后不重复安装、改连接器或检查本地配置，也不通过 shell/自写客户端
   绕开宿主工具。
2. 若当前 Agent 正运行在 ChatCut Desktop 内，不使用本 Skill。应用内置的
   项目绑定 MCP 和 Skills 是权威来源。
3. 若工具缺失，先判断正式版 ChatCut Desktop 是否已经安装并运行：未安装时
   协助安装，已安装时只需打开，然后按“恢复豆包连接”检查连接器和工具发现。
   工具暂未出现不等于连接器没有绑定。Skill 只能使用豆包已经加载到任务中的
   Connector，不能给当前任务注册或挂载缺失的 Connector；不要通过 shell
   启动独立连接进程，也不要要求普通用户理解或填写 MCP 配置。

## 发现并调用编辑操作

本 Skill 和后续工作流 Skill 中的“调用 `push_asset`、`submit_image`、
`create_project` 等”指执行对应的 ChatCut 操作；实际调用方式取决于当前
连接器暴露的入口。适用于生图、剪辑、字幕、MG、进度查询和导出等所有操作。

### 新版 Desktop：三个入口

顶层只有 `get_active_project`、`get_guidelines`、`execute` 是正常设计，
不能据此判断生图或剪辑能力缺失。

1. 直接调用 `get_active_project`，入参为 `{}`。确认项目后，直接调用同一
   连接器的 `get_guidelines`，入参也为 `{}`。这两个入口本身不通过 `execute`。
2. 从返回的 `operations` 中查找需要的操作，读取其准确 `name`、说明和
   `inputSchema`。若宿主把长结果保存为文件，读取所需操作的完整条目。
   操作清单是编辑说明，读取后不会新增一批顶层 MCP 工具。
3. 调用同一连接器的 `execute`，把操作名放入 `name`，操作参数对象放入
   `arguments`。例如，清单确认支持 `push_asset` 后，向 `execute` 传入：

   ```json
   {
     "name": "push_asset",
     "arguments": {
       "filePath": "<用户素材的绝对路径>"
     }
   }
   ```

   这里 `name` 是不带宿主前缀的操作名，`arguments` 是 JSON 对象，不能将其
   转成字符串，也不能把 `filePath` 放在 `execute` 的最外层。宿主若另有通用
   MCP 调用工具，其外层参数遵循宿主自身 schema，不与上述操作参数混用。
4. 生图同样先从清单查找对应操作（例如 `submit_image`），按实际 schema 准备
   参数，再用 `execute` 执行；生成后的进度查询和素材放入时间线也走同一路径。
   不要因为顶层找不到 `submit_image`，就判定无法生图或切换到别的服务。
5. 正常情况下复用已读清单；切换项目或收到“操作不可用”时重新确认项目并
   获取清单。只有成功读取完整操作清单、按名称和用途仍找不到所需能力时，才
   报告当前项目未提供该操作；读取清单本身失败时报告实际错误，不推断能力缺失。

### 旧版 Desktop：操作直接暴露

同一连接器没有上述三个入口、但直接提供 `push_asset` 等具体工具时，按该
工具的实际 schema 直接调用，参数无需包一层 `name` / `arguments`。不要调用
不存在的 `execute`。若同时存在新旧入口，优先使用新版流程。

## 安装正式版 Desktop

根据系统和 CPU 架构只使用匹配的官方地址：

- macOS Apple Silicon：`https://api.chatcut.io/desktop/download/macos`
- macOS Intel：`https://api.chatcut.io/desktop/download/macos-x64`
- Windows x64：`https://api.chatcut.io/desktop/download/windows`

支持 macOS 13 及以上、Windows x64；不支持 Linux。不要改用搜索结果、
第三方镜像、历史插件或托管 MCP。

1. 先检查现有安装；能正常打开时优先打开并检查连接。
2. 下载到本次操作新建的临时目录。macOS 必须阅读并遵循
   [macOS 安装验证](references/macos-install.md)。Windows 使用可见安装器，
   不绕过无效或未知发布者警告。
3. 打开刚安装的 ChatCut Desktop。若出现登录页，让用户在 ChatCut 窗口中
   自行登录；不要索取或处理密码、验证码或 Token。
4. 等待 ChatCut 完成启动，再执行“恢复豆包连接”。它会生成稳定的本地连接
   入口，但安装前已启动失败的 Connector 不一定自动重试；Desktop 已运行不
   等于连接已恢复。不要把 Connector 的实现方式、本机入口路径、命令、
   参数或环境变量展示给普通用户。

运行新下载的软件、替换现有应用或确认系统安装前，遵循宿主的可见授权流程。
下载包不完整、架构错误或源验证失败时最多全新下载重试一次。

## 恢复豆包连接

`chatcut_desktop` 是本专家需要由豆包预先加载的依赖。正常用户不需要添加、
配置或调试它。Skill 无法把缺失的 Connector 动态挂载到当前任务；运行一个
独立进程也不会让工具出现在豆包的工具目录中。

1. Desktop 启动后，优先在当前任务使用已有的 `get_active_project`；若未出现，
   使用宿主实际提供的工具搜索/发现能力查找 ChatCut Desktop 工具，不仅检查
   初始工具列表。调用成功后继续原任务；返回没有活动项目也表示连接成功，
   再按用户需求创建或打开项目。只有三个入口不属于工具缺失。
2. 仍未发现工具时，区分“连接器启动失败”和“未安装/未绑定”。首次安装前，
   预先启动的连接器可能因为找不到 Desktop 而失败；新建对话不保证会重启它。
   通过宿主实际开放的连接器管理能力或用户可见界面确认 ChatCut 连接器状态。
   状态未知时如实说明，不能直接断言绑定缺失，也不要转去操作 Desktop 界面
   或要求额外的屏幕录制、辅助功能权限来绕过连接问题。
3. 若 ChatCut 连接器显示“启动失败/运行失败”，且 Desktop 已完成启动，只重试
   这个连接器一次。若宿主确实向 Agent 暴露了原生重试/重新启动工具，先读其
   schema，再按宿主授权流程使用；不能把客户端日志里的内部方法名当作可调用
   工具。若仅用户界面支持，则请用户在豆包的 ChatCut 连接器上点击一次
   “重试/重新启动”（以实际界面为准），并告知“点完我会继续刚才的剪辑”。
   不要求用户重新安装专家、添加重复连接器或重新填写原始需求。
4. 等待本次重试结果，再在当前任务重新发现工具并调用 `get_active_project`。
   只有原生调用成功才报告连接完成，随后直接继续原任务。READY 是连接器就绪
   的证据，不代替实际调用验证；已经 READY 的连接器不重复重启。重试仍失败时
   保留实际错误并停止自动重试，交由发布方排查，不循环新建任务或重启客户端。
5. 仅当连接器已 READY，但重新发现后当前任务仍无法加载工具，才建议最多新建
   一次任务；说明这是刷新会话工具的尝试，不保证成功，也不代替重试连接器。
   延续原始剪辑要求，原样保留素材路径，不改写路径中的空格。新任务仍无工具时
   停止并报告“连接器已就绪，但任务没有加载工具”，不要误报 Desktop 安装失败。
6. 只有确认专家确实缺少对应连接器依赖时，才请发布方检查安装/绑定。状态未知
   时报告尚未确认的环节。不要让普通用户填写命令、参数、环境变量或本机入口
   路径；不要修改豆包的 Preferences、LevelDB、Cookie、连接器数据库或审批
   记录，也不要通过 shell、自写客户端或直接运行本机入口冒充豆包原生连接。

## 执行剪辑

1. **确认项目**：若用户明确要求“新建/创建一个项目”，先按上述调用方式执行
   `create_project` 操作，确认 Desktop 已切换到返回的 projectId，再导入或编辑；
   不得因为当前已有活动项目而沿用它。否则先读活动项目和时间线。非平凡修改
   前读取最新状态，不猜项目 ID、轨道、素材、帧率或画布。
2. **对齐目标**：只询问会改变成片方向、且无法从素材和项目得到的信息。
3. **准备素材**：本机文件使用 Desktop 的 `push_asset` 注册到当前项目；
   传入用户给出的绝对路径，或宿主为附件解析出的可读本地路径，且调用参数中
   必须显式包含 `{"filePath":"<绝对路径>"}`（新版放在 `execute.arguments` 内）。
   公开 URL 使用当前工具和同步 Skill 中真实存在的导入能力。不要先拼成扁平
   视频，也不要创建托管版 `import_media` 会话。若工具报告缺少 `filePath`，先查看宿主工具卡的实际
   入参；新版检查 `execute.arguments.filePath`，旧版检查直接入参的 `filePath`。
   参数为空时只允许用精确参数对象重试一次。仍为空则停止并报告
   “宿主未把必填参数发送给 ChatCut MCP”，不要循环改写参数、误判成文件权限
   或绕到旧项目复制素材。
4. **设置画布**：用户指定比例时优先；Shorts、Reels、TikTok 默认 `9:16`，
   横版 YouTube 默认 `16:9`，否则跟随主视觉。放入第一个视觉素材前设置并
   读回目标时间线。
5. **先结构后包装**：先完成口播精剪、叙事节奏和镜头编排，再处理字幕、
   B-roll、转场、滤镜、音频和 Motion Graphics。
6. **使用真实契约**：新版以 `get_guidelines` 返回的操作 schema 为准，旧版以
   直接暴露的工具 schema 为准；不臆造参数或返回值。
7. **付费生成门禁**：执行任何可能消耗 ChatCut credits 的 `submit_*` 操作前，
   说明内容、数量和关键规格并取得明确确认；失败后不要自动重复扣费任务。
   通过 `execute` 执行时同样适用。直接编写可编辑 Motion Graphics 不属于付费生成。
8. **验证**：工具成功只证明请求被接受。用项目读取、字幕/转写状态、生成进度
   和可用预览核对结果；用户可能同时手动修改，关键步骤后重新读取状态。
9. **交付**：默认交付可继续编辑的时间线。仅在用户明确要求时启动导出，并
   等待到真实文件完成。

## 边界与输出

- 先说结果，再说必要状态、验证证据和下一步；未验证的计划不写成已完成。
- 所有项目变化都应直接出现在 ChatCut Desktop，不返回网页编辑器地址。
- 不处理 ChatCut 或豆包密码、验证码、OAuth Token、Cookie 或其它密钥。
- 不承诺实时屏幕/摄像头录制，不直接修改 Premiere Pro、DaVinci Resolve 或
  Final Cut Pro 工程，也不直接向社交平台发布或排期。
